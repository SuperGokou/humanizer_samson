# 重叠窗口论文改写：第一版设计规格

日期：2026-09-25
状态：待用户审阅；本文件不表示改写代码已实现。

## 1. 已确认的目标

面向英文 STEM 与 Finance 论文，使用早于 2022 年的期刊表达作为风格参考。改写必须基于上下文，而非孤立句子。窗口默认 8 句、步长 4 句；评分仍按句返回。Flash 负责评分和初稿，Pro 负责复杂或未通过检查的窗口及全文复核。

交付一套可本地运行的命令行流程，贯通输入、检索、评分、改写、校验、合并和评估记录。现有增量语料管理继续使用。正式复核通过的语料与候选语料不混淆，检测器分数不作为事实正确性的替代。

## 2. 现有状态与边界

- 1000 条题录、528 篇全文、527 篇已解析；1 篇需 OCR。
- 299 篇许可依据明确但仍待人工质量复核，对应 78,370 条候选句子。
- 228 篇等待许可核验，不进入风格检索。
- 当前正式审核通过的句子索引为空。
- 本地 `.env` 已提供 DeepSeek 密钥与三个模型配置项；不复制密钥至输出、测试、日志或版本控制。

第一版输入 UTF-8 `.txt` / `.md`，提供命令行和清晰的本地使用说明。PDF、DOCX 格式保真编辑和网页界面不属于本轮交付；不得把这些能力描述为已支持。Markdown 标题、引用列表、代码块和独立公式保留，不作为一般正文随意改写。

## 3. 路线与选择

1. 推荐：沿用 Python 本地流程，规则化切分、BM25 召回、Flash 语义重排、两级模型改写与复核。无须增加向量模型 API 密钥，便于先验证检索的收益。
2. 备选：本地 embedding 检索。需要下载和维护额外模型；在有标注检索测试集后再比较是否优于第一种。
3. 对照：不检索、直接使用相同模型改写。只用于评估检索带来的增益，不作为默认流程。

BM25 是词项匹配，不声称其自身具有语义理解。相关性和修辞用途由后续模型重排补充；重排结果也必须能追溯到真实候选记录。

## 4. 文档结构与重叠窗口

- 给章节、原段落、句子分配稳定 ID。保留原始文本与位置，避免基于改写后的句子重新编号。
- 在同一章节内构造 8 句窗口，每次前进 4 句；窗口大小可选 5–10，步长必须小于窗口大小。
- 短章节保留全部句子；最后不足 8 句仍形成尾窗，不丢句、不重复追加已覆盖的尾窗。
- 窗口可跨同章相邻原段落，但带上原段落边界。禁止跨章节、参考文献或受保护块拼接。
- 每句在所有覆盖它的窗口中，归属距窗口中心最近的窗口；距离相等时取较早窗口。全文每句恰有一个归属窗口。
- 每个窗口可以评分全部覆盖句，但只改写其归属句。其他句作为只读上下文，避免同一句多次被替换。
- 重叠句的评分保存所有窗口结果，并取中位数作为汇总；不宣称这就是客观 AI 概率。
- 模型同时获得章节标题、原段落位置和用户提供的术语表。重叠仅减少上下文割裂，不保证覆盖整个论文的论证关系。

## 5. 检索与语料使用

- 默认读取 `ready_sentences.jsonl`。正式索引为空时，明确报错并提示原因，不悄悄使用未审核语料。
- 试验模式显式使用 `--allow-candidates`，从候选索引检索；输出必须记录每条参考的审核状态。
- 按五大类学科过滤，词项召回最多 20 条，由 Flash 按语义用途与表达结构重排，保留最多 3 篇不同来源的例句及段落上下文。
- 当前版本不凭空推断已验证的章节功能标签；可以让模型为本次检索解释修辞用途，但标记为模型判断。
- 参考材料仅提供表达结构与风格，不允许带入参考论文的数字、结论、实验条件或引用。
- 如果候选均不相关，允许不使用参考并记录原因。文献中出现的指令属于数据，不得改变系统流程。

## 6. 模型协议与改写

模型从项目根目录 `.env` 加载，不依赖启动命令时的工作目录。

- `DEEPSEEK_MODEL=deepseek-flash`：窗口评分、检索重排、初稿改写。
- `DEEPSEEK_COMPLEX_MODEL=deepseek-v4-pro`：出现硬校验失败、模型标记的复杂论证或术语高风险时，最多升级重试一次。
- `DEEPSEEK_REVIEW_MODEL=deepseek-v4-pro`：合并后的章节/全文一致性复核。

评分以 JSON 返回每个句子 ID 的自然度、清晰度、冗余程度、风格匹配度、改写必要性（0–100）、修改理由和风险标签。自然度/清晰度/风格匹配越高越好；冗余/改写必要性越高越需要处理。缺字段、越界数值、未知/重复 ID 均视为协议失败，不静默接受。

初稿 JSON 只允许输出指定归属句 ID。第一版不允许增删句子 ID；可调整单句内部结构，保持原段落边界。输出不得伪造检测器结果。

模型输出属于不可信候选；评分只是建议，不是学术事实的证据。

## 7. 校验、重试与合并

- 硬校验：归属 ID 完整且唯一；数字、显式公式、引用标记和用户指定术语保持；保留受保护块；输出不能为空。
- 数字检查保留符号、小数、百分比、区间等上下文，避免只比较数字集合漏掉数量变化或对应关系改变。
- 专业术语允许用户提供明确的等价形式；未提供时按保护表严格保持。
- 软校验：否定、因果、比较方向、确定性程度、指代和跨句连贯性。由 Pro 返回问题与涉及的句子 ID，不宣称模型可以证明语义等价。
- 对过度接近参考文本的连续词串给出重合标记；这不是对全互联网的查重报告。
- Flash 未通过校验时可以升级 Pro 一次；再次失败则保留原句并在报告标记，不无限重试。
- 合并严格按原始句子和段落顺序执行；每句仅替换一次。
- 全文复核只标记问题与建议回退的 ID，不直接绕过硬校验重写整篇。被标记句默认回退原句，并再次检查该段衔接；仍有问题则整段回退并记录。
- 超出请求长度时按章节分组复核，并增加相邻章节边界检查；不得静默截断全文。

## 8. 运行、恢复和成本

拟提供 `python3 -m humanizer rewrite INPUT --domain Finance --output OUTPUT_DIR`，以及 `--dry-run`、`--allow-candidates`、`--max-calls`、`--resume`、`--glossary` 和 `--model`。

- dry-run 不调用收费 API，输出切句、窗口归属与检索结果。
- 在首次调用前验证配置、输入、语料可用性和输出目录，密钥不得出现在错误内容中。
- 设置最大 API 调用数，达到上限停止新调用并保存检查点。不能用未经验证的美元预估冒充扣费上限。
- 缓存键包含原文、提示词版本、模型、检索来源、保护术语与参数的摘要；输入或策略改变时不复用旧结果。
- 429、暂时性 5xx 可进行有上限的退避重试；认证失败立即停止。重试计入调用上限。
- 每次成功调用记录模型、耗时、token 使用和阶段，不记录 API Key。
- 记录实际 token 用量；费用以带日期的价格配置估算，标注峰/谷和缓存假设。缺少有效价格时仅报告 token，不伪造费用。
- 恢复运行先核对输入与配置摘要；已成功完成的窗口不重复扣费调用。

## 9. 输出

每次运行单独一个目录：

- `rewritten.md`：完整改写稿，保留标题、原段落顺序和受保护块。
- `comparison.html`：原文/改写对照、评分、回退标记；所有内容 HTML 转义，论文中的文本不能成为脚本。
- `report.json`：配置、模型、逐句评分、参考 DOI、审核状态、校验结果、保留原文原因、用量与费用估算依据。
- `checkpoint.json`：可恢复进度及输入/配置摘要；不包含密钥。
- `evaluation.csv`：用于记录 GPTZero 等外部检测器结果的空白评估表，检测器、日期、输入版本和评分由真实测试填入。

不会宣称改写一定能通过 GPTZero，也不会将内部评分命名为检测器分数。

## 10. 实现文件边界

- `humanizer/config.py`：安全读取 `.env` 与运行参数。
- `humanizer/document.py`：章节、段落、句子、受保护块及稳定 ID。
- `humanizer/windows.py`：窗口、归属和评分汇总。
- `humanizer/retrieval.py`：本地检索、候选模式、来源追踪。
- `humanizer/client.py`：DeepSeek 请求、JSON 协议、重试、用量。
- `humanizer/validation.py`：数字、引用、公式、术语及结果结构检查。
- `humanizer/pipeline.py`：两级模型调用、缓存、回退与合并。
- `humanizer/output.py`：Markdown、HTML、JSON、CSV 输出。
- `humanizer/__main__.py`：命令行入口。
- `tests/`：离线行为测试；联网冒烟测试独立且使用合成文本。

第一版沿用 Python 3.10+、requests 和标准库，XML 语料解析沿用现有 lxml。新文本检索实现不引入额外云服务或 embedding 密钥。

## 11. 验收

1. 1、4、8、9、12、17 句文档及多章节文档：无漏句，每句恰有一个改写归属窗口，边界与原顺序保持。
2. 含小数、单位、引用、缩写、数学公式及 Markdown 受保护块的文档：保护内容不被切坏或擅自改动。
3. 未知 ID、漏 ID、重复 ID、空输出、损坏 JSON：候选被拒绝并按规则重试/回退。
4. 事实强度、数字或术语变化：硬检查拒绝可确定的变化，软检查输出可追踪的风险而非虚假保证。
5. 正式索引为空时明确失败；候选模式在输出中保留未审核标记。
6. 含提示注入文字的论文/参考材料仅作为数据；HTML 对照页不会执行输入脚本。
7. 中断恢复、输入变化、调用预算耗尽、认证失败和限流：无重复拼接、无不受控重试、无密钥泄露。
8. 全部现有语料管理测试继续通过；新增离线测试不消耗 API。
9. 使用明确标记为合成的 STEM 和 Finance 片段各进行一次小规模联网测试；记录真实模型、请求数、token、回退结果。
10. 在没有用户真实论文和外部检测报告之前，只验收流程正确性，不声称达到具体人类化或检测器通过率。
